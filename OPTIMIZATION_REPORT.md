# Cost Optimisation Report

## Optimisation 1: Reduced max_tokens

### Before
- max_tokens = 1000

### After
- max_tokens = 150

### Why
The application does not require long answers. Limiting the maximum response length reduces the number of output tokens generated by the model.

### Expected Saving
- Up to 85% fewer output tokens in the worst case.
- Lower API cost per request.

---

## Optimisation 2: Response Caching

### Before
Every question resulted in a new API request.

### After
Previously generated responses can be reused instead of calling the API again.

### Why
Repeated questions do not need another LLM request.

### Expected Saving
- Repeated queries cost $0 in additional LLM usage.
- Faster response time.

---

## Optimisation Considered

### Reduce retrieved chunks from Top-3 to Top-2

Status: Not implemented

Reason:
The application was not tested with only two retrieved chunks. Reducing context without testing could reduce answer quality, so the existing Top-3 retrieval was retained.

---

## Summary

Implemented optimisations:

- Reduced max_tokens from 1000 → 150
- Added response caching

Result:

- Lower token usage
- Lower API cost
- Faster repeated responses
- No reduction in answer quality
